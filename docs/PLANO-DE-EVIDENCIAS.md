# Plano de evidências — Git e GitHub

Este arquivo organiza as capturas necessárias para demonstrar as etapas do laboratório. As evidências devem ser capturadas diretamente do GitHub, terminal ou navegador após executar cada atividade. **Não substitua capturas reais por imagens montadas.**

## Checklist

- [ ] E1 — Repositório pessoal e relação com o modelo/fork (se aplicável).
- [ ] E2 — Configuração de colaborador e convite aceito; se não houver dupla, registrar a limitação.
- [ ] E3 — Clone e saída de `git remote -v` no computador.
- [ ] E4 — Histórico do GitHub com commit identificável do aluno.
- [ ] E5 — `git pull` concluído e alteração recebida.
- [ ] E6 — Push de uma alteração feita pelo segundo integrante.
- [ ] E7 — `git log --oneline --graph --all` mostrando históricos divergentes e merge automático.
- [ ] E8a — Arquivo após resolução de conflito, sem marcadores.
- [ ] E8b — Página aberta no navegador após a resolução.
- [ ] E9 — Aba **Branches** com as branches do exercício.
- [ ] E10 — Pull Request integrado, com revisão/comentário real.
- [ ] E11 — Pull Request com conflito antes e depois da resolução.
- [ ] E12 — Histórico final e página com Início, Sobre e Contato.

## Como nomear os arquivos

Use nomes consistentes, por exemplo:

```text
evidencias/
  01-repositorio.png
  02-colaborador.png
  03-clone-remotes.png
  ...
  12-historico-final.png
```

## Registro de limitações

As etapas que dependem de duas contas, dois ambientes ou de ações humanas (aceitar convite, revisar e aprovar PR, comentar linha a linha) só devem ser marcadas como concluídas depois de executadas. Anote aqui qualquer etapa adaptada e o motivo.
