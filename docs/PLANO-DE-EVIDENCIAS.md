# Plano de evidências

A entrega pede um PDF individual chamado `SCM_<NomeCompleto>.pdf`, com cabeçalho, URL do repositório e capturas numeradas/legendadas. As capturas precisam ser reais, legíveis e mostrar o usuário conectado e a data/hora do sistema.

## Capturas exigidas pelo roteiro

- [ ] **01 — Fork (Aluno A):** página inicial do fork mostrando “forked from…”.
- [ ] **02 — Colaborador (Aluno A):** Settings → Collaborators com o Aluno B listado.
- [ ] **03 — Clone (ambos):** terminal com `git clone` e `git remote -v`.
- [ ] **04 — Primeiro commit (Aluno A):** aba Commits do GitHub.
- [ ] **05 — Pull (Aluno B):** saída de `git pull` e `index.html` com o título atualizado.
- [ ] **06 — Push (Aluno B):** saída de `git push` concluído com sucesso.
- [ ] **07 — Merge automático (ambos):** `git log --oneline --graph --all` mostrando a bifurcação e o commit de merge.
- [ ] **08a — Conflito (Aluno B):** `style.css` após a resolução, sem marcadores.
- [ ] **08b — Página (ambos):** navegador mostrando o estilo combinado.
- [ ] **09 — Branches (ambos):** tela Branches do GitHub com as três branches exigidas.
- [ ] **10 — Revisão (Aluno A):** PR marcado como Merged, com comentário e aprovação real do Aluno B.
- [ ] **11 — Conflito no PR (Aluno B):** o mesmo PR mostrando o aviso de conflito antes e Merged depois.
- [ ] **12 — Resultado final (ambos):** histórico `git log --oneline --graph --all` e navegador com o menu completo.

## Outras verificações antes de entregar

- [ ] Confirmar se o repositório usado atende ao requisito de fork do modelo do docente.
- [ ] Executar as etapas locais no Git/VS Code; não basta o histórico de edições feitas pelo site.
- [ ] Fazer revisão com o colega de verdade. Não inventar aprovação, comentário ou participante.
- [ ] Executar `git revert` em um commit de teste e registrar o resultado.
- [ ] Preencher o documento `ENTREGA-EVIDENCIAS.md`, exportar para PDF e revisar a legibilidade.

Os arquivos atuais do projeto e os PRs já existentes ajudam como base, mas não substituem as evidências das etapas que ainda não foram executadas. Não marque uma caixa como concluída até ter a captura correspondente.
